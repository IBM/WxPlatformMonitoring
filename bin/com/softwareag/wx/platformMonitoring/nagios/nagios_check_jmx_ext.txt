Usage: check_jmx_ext -U url -O object_name -A attribute [-K compound_key] [-I attribute_info] [-J attribute_info_key] -w warn_limit -c crit_limit [-v[vvv]] [-help]

, where options are:

-help 
	Prints this page
	
-U 
	JMX URL, for example: "service:jmx:rmi:///jndi/rmi://localhost:1616/jmxrmi"
	
-O 
    Object name to be checked, for example, "java.lang:type=Memory"
    
-A 
	Attribute of the object to be checked, for example, "NonHeapMemoryUsage" (optional, if operation is provided)
	
-K 
    Attribute key for -A attribute compound data, for example, "used" (optional)
	
-I
    Attribute of the object containing information for text output (optional)
    
-J 
    Attribute key for -I attribute compound data, for example, "used" (optional)

-v[vvv]
	verbatim level controlled as a number of v (optional)

-w 
	warning integer value

-c
	critical integer value

-operation
	Name of operation to invoke on object (optional, if attribute is provided)
	
-expected
	Expected value to check returned reading against. If set, -w and -c aren't used (optional, if -w and -c are provided)
	
-params
	Parameter list for JMX operation. Provide as comma separated. String values must be enclosed in ". Integer values mustn't be enclosed in ". Example: -params "1,500,\"Some String\",\"Another String\"". Note the encolosing " are necessary. Note that the String " are escaped. (optional if no operation is used, or if the operation has no input parameters)

-signature
	List of input parameter types. Must match the number of parameters. Valid values: String, Integer. Example: -Signature "Integer, Integer, String, String". Note the encolosing " are necessary. (mandatory if -params is provided)

-loglevel
	Default=0. 0 is log level INFO, 1 is log level DEBUG. Example: -loglevel 1


Note that if warning level > critical, system checks object attribute value to be LESS THAN OR EQUAL warning, critical
If warning level < critical, system checks object attribute value to be MORE THAN OR EQUAL warning, critical
